## 结论与范围

录像 `chessboard-05.avi` 的第 165、174、182、192、214 帧均可复现空隙误配。错误灯条对满足当前几何条件，中央支架或背景亮纹理又满足中央连通域条件，因此与正确装甲板同时输出。当前中央图案检查不识别数字身份，不能充分拒绝这类负样本。

两份用户指定参考项目均在几何配对后执行数字分类。本轮固定使用本项目灯条端点，按参考方法提取数字并运行其 ONNX 模型：五个错误配对均为 `negative`，五个正确配对均为 `2`。两份模型文件相同，这是一组模型对指定样本的分类器对照，不是两个独立模型验证，也不是运行完整 ROS 检测器的结果。

预览只绘制检测结果，没有接入跟踪观测和状态。本次应用回放实际有 392 帧处于 `tracking`；看不到跟踪框不能据此认定内部没有跟踪。现有跟踪是视线角和距离的差分预测，尚不具备旋转轨道估计、固定守点、云台到位判定及到点开火决策。

本轮完成离线调查、源码审查和证据整理。软件生产源码、算法默认参数和运行入口均未修改；所有应用验证为 dry-run。新策略的实现与现场效果尚未完成。

### 为什么现有检查没有拦住

1. [配对循环](../src/vision/traditional_detector.cpp) 枚举同色灯条对。错误候选的长宽、长度比和矩形误差均在允许范围内，而且候选内没有另一根已接受灯条，第三灯条检查无法排除相邻两甲间的空隙。
2. 中央图案矫正为 64×56，灯条端点在 y=16/40，中央 ROI 为 38×56。默认最小连通域高度是灯长 24 的一半，即 12 px；面积范围约为 42.56–1276.8 px²。表中的 13–15 px、62–99 px² 亮结构均满足这两项。
3. 这些小亮结构同时满足居中、跨中线、不触上下边界等条件，因此 gate 返回 true。其中央对比度依次为 31、29、29、23、29，均超过默认门限 6。第 165 帧错误连通域质心约 `(27.747,21.495)`，仍在 x≤28.5、y≥19.6 的允许区间。
4. 当前没有共享灯条候选的冲突决策。正确配对和错误配对可以共享一根灯条，同时进入 PnP 和跟踪候选集合。

第 192 帧错误配对的矩形误差 1.264° 小于正确配对的 3.140°。因此仅收紧矩形误差、按最矩形优先贪心配对，不能可靠解决整组问题。抬高图案高度能拦住本组小亮结构，但上一轮已存在暗数字、粘连和遮挡漏检，不能只为这五帧硬调阈值后声称问题解决。

整片默认输出累计 495 个候选，关闭图案 gate 后累计 1147 个；默认有 394/395 帧至少一个候选。这些是候选计数，没有逐帧真值，不能转换为精确率或召回率。

## 预览为什么没有跟踪框

`AutoAimPipeline::process()` 在第 25–28 行依次执行候选选择、跨帧跟踪和弹道解算。但 `main.cpp` 第 248–257 行只调用检测器 `draw_debug()`，向 `DebugViewer` 传入图像、Frame 和 DetectionResult。`DebugViewer::show_drawing()` 第 100–135 行没有接收 `TargetTrackEstimate`，信息栏也只有 frame/time/lights/armors。

因此当前绿色四边形是全部检测候选，黄色矩形是候选 ROI；它们不表示已选中或已跟踪目标。内部跟踪可能从多候选中选择与单帧 selector 不同的观测，后续可视化应使用 tracker 的 `current_observation`，不能仅突出 selector 的 `selected()` 后称为跟踪框。

带当前内参的 395 帧应用回放中，状态为 detecting 2 帧、tracking 392 帧、temporarily_lost 1 帧；五个指定帧均为 tracking。现有 CSV 没有记录实际关联候选的完整像素角点和 ID，这组统计证明跟踪链路在运行，不能证明始终跟踪正确装甲板。外参未标定，也不能用本次回放确认实际距离、目标速度或云台控制精度。

建议后续同时显示全部检测候选、实际跟踪观测、暂失预测位置及状态；再接入轨道、守点、到点剩余时间和每个禁火原因。不可见预测应与可见检测明确区分。

## 用户策略与当前实现的逐项对照

| 用户要求 | 当前证据与差距 |
| --- | --- |
| 估计旋转中心、半径、相位与转速 | `TargetTrackEstimate` 仅有 yaw/pitch/range 及差分速度；yaw 是装甲位置的视线角，不是轨道相位。没有圆周状态或轨道拟合。 |
| 短暂不可见继续预测，重现立即校正 | tracker 的 temporarily_lost 可短时外推，再次观测会更新；默认最多连续 miss 3 帧、预测年龄 0.15 s。AimCompensator 只接受 tracking，暂失预测没有用于保持/预置守点。 |
| 固定守点，只在明显变化时重新定位 | 有效时每帧采用最新 aim 角度；SafetyController 不保存守点，没有重定位阈值或滞回。 |
| 不可见期间保持角度且禁止开火 | 暂失会令 aim invalid，安全输出将 fire 清零，但同时把 yaw/pitch 归零；不等于保持上一次有效守点。当前正常调用链对不可见禁火已有保护。 |

| 目标状态足够可靠 | 有确认次数、时间有效性、预测有效性和数值检查；没有轨道残差/协方差、相位不确定度、数字置信度、姿态质量共同构成的可靠度门控。 |
| 弹丸和装甲到点时刻匹配 | 现有补偿迭代使用视线匀速模型和飞行时间逐帧追瞄；没有固定守点的过点时刻、到点窗口或相位窗口。 |
| 云台稳定到位才允许开火 | 正式状态帧含 yaw/pitch，但当前决策只用弹速与状态新鲜度，没有将回传角与命令比较，也没有反馈角速度、稳定持续时间或到位门限。 |
| 命中装甲内部并留余量 | 现有无阻力恒重力模型计算点目标角度/飞行时间；没有与未来装甲平面求交、板内边界、弹丸尺寸及误差余量检查。旋转中心只应服务建模，不能作为默认命中点。 |
| 每发都满足条件，条件失败立即撤销 | 现有 SafetyController 在每次 step 决策；应用始终使用默认 `allow_visual_fire=false`，也没有设置 `visual_fire_intent=true`。尚无生成好窗口、逐发重评或发送命令有效期的决策层。 |
| 不论开火与否持续发送完整协议帧 | live 启动独立发送线程，默认每 10 ms 编码完整 ID1+ID2 共18字节，不按 fire_flag 分支省略记录；dry-run 不启动串口。已有软件实现。 |

具体安全路径：`AimCompensator::solve()` 第 30–41 行要求 tracking、有效预测、历史观测和有效弹速；`SafetyController::decide()` 第 136–168 行还要求通信、图像及处理有效，开火需同时满足 `allow_visual_fire` 和 `visual_fire_intent`。`AutoAimRuntime` 当前没有设置视觉开火意图，`main.cpp` 第 203–209 行构造默认安全控制器。

持续发送路径：`SelfAimTransport::transmit_loop()` 第 307–339 行每周期调用 `encode_command(command())`，完整写入成功才增加发送计数。当前保存的 command 没有产生时刻或过期时间；未来开放开火意图前，需在发送侧独立检查命令有效期，避免算法阻塞期间重复旧的开火请求。当前应用默认始终禁火，本轮没有触发非零请求。

`PoseSolver` 当前仅用固定相机→云台外参，将目标位置转换为云台坐标系视线角；实时回传姿态尚未参与轨道所在稳定坐标系的变换。固定世界守点和云台到位比较需要统一坐标参考、符号及时间；相关现场确认已有清单并在本轮补充细化。

用户最终要求按“目标不可见期间禁止开火”执行：暂失预测可继续估计状态、保持或预置角度，但不能单独放行开火。即使短时外推置信度高，也不能覆盖这一限制。

## 离线时间基准的额外问题

`FrameSource::read_capture()` 保留了 `source_time_seconds`，本录像每帧文件时间间隔为 0.00625 s。但 `stamp()` 第 240–251 行为视频使用处理时的 `steady_clock::now()`；`AutoAimRuntime::step()` 第 74–75 行将这个时间传给 tracker，速度差分没有使用文件时间。

本次回放帧间处理时间最小 0.002249 s、中位数 0.0032975 s、最大 0.039112 s，均不等于固定的文件时间间隔。GUI 的播放限速和暂停也会改变估计速度；暂停后间隔超过默认 0.25 s 会触发跟踪重置。当前单步预览适合定位检测问题，不能用来定量验证真实转速和到点预测。

后续应分开管理观测/运动时间和安全决策的墙钟时间：离线运动估计使用录像时间轴，真实相机使用可信采集时刻；图像新鲜度、通信新鲜度、发送命令过期仍使用单调实时钟。文件 FPS 生成的时间轴也不等于已经验证了实际采集节奏，需要采集时间戳/记录元数据支持。不能简单用历史视频时间替换安全检查的当前时钟。

现有 tracker 固定前视默认 0.05 s，补偿层额外延迟默认 0 s，再迭代叠加弹丸飞行时间。前视默认值没有实测标定，飞行时间结果也没有表示完整的观测至命中总时延；后续应明确每段时延及日志定义，避免漏算或重复补偿。

## 建议的后续实施顺序与验收

### 1. 检测质量、可视化和可重复回放

先为这15帧及上一轮已知漏检整理真值，覆盖暗数字、支架亮纹理、粘连、模糊和遮挡；同一录像相邻帧高度相关，最终还需要独立录像。将参考数字/negative 分类作为候选筛选方案评估，验证阴性拒绝和真实目标保留，再决定集成。共享灯条的候选冲突处理应结合内容证据、PnP质量和运动关联评分；第192帧说明单用矩形分数不够。

同时接入实际跟踪观测和状态的可视化，完善关联日志并修正离线运动时间基准。验收应检查特定错误配对被拒绝、正确配对保留、旧暗目标不回退以及不同播放速率下运动估计一致。启动器smoke测试还应使用独立配置，避免用户标定路径影响小尺寸fixture。

### 2. 旋转状态估计

在稳定且时间对齐的坐标系内维护轨道中心、轨道平面、半径、相位、角速度及质量指标。一般圆周可表示为 `p(t)=c+r[u*cos(theta(t))+v*sin(theta(t))]`，其中 u/v 是轨道平面的正交基，`theta(t)=theta0+omega*(t-t0)`。目标单靶的具体旋转轴和板姿态关系需要数据支持，不假定参考机器人多甲模型必然适用。

观测有效则校正，短失只外推且不请求开火，长失/残差或不确定度超限则失效并进入重新捕获。用已知轨道和角速度的合成序列验证噪声、异常观测、方向反转、短失恢复、长失和相位跨界，再用正确时间轴的标注录像验证。

### 3. 固定守点和非发射控制

从可见且适于命中的轨道段选择装甲未来位置，计算对应弹道角并锁存。设置守点更新阈值、最小保持时间和滞回，持续修正轨道与到点时刻，但稳定条件下不逐帧改角。暂失保持有效守点或预置下一位置，同时禁止开火；长失进入明确的重新捕获/搜索状态。

分别验证轨道状态变化与云台命令变化：不应把轨道每帧更新直接等同于云台每帧运动。反馈角度与命令必须处于同一参考系，之后才能验证误差、反馈角速度和稳定持续时间。

### 4. 择机开火决策与连续发帧

沿用用户严格要求，把可见性、可靠状态、有效弹速、云台到位稳定、弹道可达、命中区域及到点时间窗口组成同一决策。以观测时刻为起点，传播到预计命中时刻；总预测间隔应包括观测年龄、命令/发射延迟和弹丸飞行时间。固定守点的弹道必须与该时刻的装甲平面/内部区域相交，并计入弹丸尺寸及标定、预测和弹道误差余量。

好窗口内可持续评估多个发射机会，每次请求及实际可能离膛时刻均要在有效窗口内；任一条件失败，后续完整帧的 ID2 立即为0。发送线程应有独立命令有效期。先用合成目标、反馈序列和模拟CDC验证上述失效路径，保持正式应用默认禁火，再按 `questions.md` 统一安排现场验证。

正式协议只给开火请求标志和弹速，没有逐发确认、弹量或命中事件字段。持续发送非零请求的帧数不能作为发射次数；实际脉冲/电平响应、射频与取消后剩余发射延迟需现场确认。比赛以靶板传感器判定、固定50发为分母，软件不能用自定义计数替代。
