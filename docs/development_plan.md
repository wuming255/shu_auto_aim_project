# 上海大学 SRM 自瞄赛道项目开发规划

> 本文档用于保存当前阶段的总体开发方向，不作为一次性锁死的实现规格。
> 随着规则、硬件、现场测试结果和算法效果逐步明确，阶段边界、技术路线和优先级可以调整。
>
> 需要用户后续亲自上车、接线、标定或进行安全操作的内容，统一记录在项目根目录的 [`questions.md`](../questions.md) 中；本文档只描述软件开发规划，不替代现场操作清单。`questions.md` 中的现场测试统一安排在软件主体全部完成并通过本地、离线和模拟验证之后，不作为每轮开发结束时的调试要求。

## 1. 项目目标

在不修改下位机、发射机构、安全急停和机械限位的前提下，逐步完成自瞄赛道上位机闭环：

```text
相机采集
  -> 目标检测
  -> 目标解算
  -> 目标跟踪与预测
  -> 云台瞄准
  -> 视觉开火请求
  -> 正式 USB CDC 通信
```

最终效果、实时性、参数和安全行为以比赛规则、正式通信协议和现场设备实际表现为准。

## 2. 规划原则

- 规则和正式通信协议优先于参考项目和临时假设。
- 参考项目优先采用“直接复用 → 小幅修改 → 重构 → 重新实现”的顺序。
- 参考项目的通用串口、相机、视觉、解算和工具实现可以作为候选复用对象；旧版自瞄通信协议不直接复用。
- 每个阶段先建立可验证的最小功能，再向下一阶段推进。
- 优先保证可观察性、可回放性和安全性，再追求更复杂的算法和更高性能。
- 现场条件未确认前，不把设备型号、标定结果、帧率、延迟或控制参数写死在代码和文档中；使用配置项、接口和模拟数据保留适配空间。
- 开发阶段默认依据校内赛规则、正式通信协议、参考项目和本地/离线环境推进，不把每轮现场操作当作阶段完成条件。
- 真实 NUC、相机、下位机、云台和发射相关验证集中放在软件主体完成后的最终现场验证阶段，具体步骤只写在 `questions.md`。
- 阶段可以根据实际工作量合并、拆分、调整顺序或增加专项验证轮次。

## 3. 当前总体阶段

当前暂按约 **8 个核心阶段** 规划。这里的“阶段”不是不可变的开发承诺，实际开发时可以拆成多个小轮次；如果某阶段验证结果不满足验收标准，应优先修复或回退，不强行进入下一阶段。

### 阶段一：工程基础与正式协议

**状态：已完成基础版本。**

计划范围：

- 建立项目说明、开发规范、长期文档和开发日志；
- 实现正式自瞄协议的帧编码、解码和流式解析；
- 建立最小 CMake 工程和协议测试；
- 明确参考项目旧通信协议与本次正式协议的边界。

后续如发现正式协议、字段语义或赛务通知发生变化，应优先更新协议文档和测试，再调整实现。

### 阶段二：CDC 串口传输层

**状态：已完成基础版本。**

计划范围：

- 建立正式协议对应的串口传输适配层；
- 处理后台收发、有限超时、设备不存在、断开和重连；
- 提供最新下位机状态和通信统计；
- 用伪终端或模拟数据验证通信线程和拆包行为；
- 保持默认非开火状态。

后续需要根据真实设备行为决定是否补充设备稳定识别、状态超时、生命周期重启和更细粒度错误分类。

### 阶段三：运行环境与输入抽象

**状态：已完成离线/通用 OpenCV 输入抽象基础；现场工业相机适配仍待最终统一现场验证。**

计划范围：

- 根据规则中已经明确的目标硬件和参考项目实现，建立相机输入接口及可替换适配层；
- 检查当前开发环境可用的编译器、依赖和 SDK，并为缺失的现场依赖保留可选适配或模拟实现；
- 支持离线图片、离线视频和模拟输入，必要时再提供实时相机入口；
- 优先形成可以独立运行和诊断的输入 smoke test；
- 将设备相关配置与算法参数分离。

本阶段已完成不依赖现场设备的输入基础：图片、视频文件和 OpenCV camera index 的统一帧接口、时间戳、序号、EOF 和循环处理。海康 MVS 专用适配器、现场 SDK 路径、真实分辨率、曝光和采集参数保持可配置，待项目主体完成后的统一现场测试再确认。

### 阶段四：传统视觉检测基线

计划范围：

- 优先评估和复用参考项目的传统视觉组件；
- 建立灯条、颜色、几何关系和装甲板候选筛选流程；
- 支持检测结果可视化和离线回放；
- 记录检测帧率、漏检、误检和图像质量问题；
- 先针对本次单个原地旋转装甲板场景裁剪范围。

检测方法、阈值、ROI 和必要的图像预处理参数不在当前阶段提前固定，优先依据参考项目、规则给出的靶标尺寸和可获得的离线/模拟数据逐步确定。真实靶标现场采样属于最终统一现场测试，不作为本阶段结束条件。

如果传统方法经过验证无法满足稳定性要求，再单独评估是否引入参考项目中的神经网络模型和 OpenVINO 方案。

### 阶段五：几何解算与静态瞄准

计划范围：

- 接入相机内参和畸变参数；
- 复用或改造装甲板 PnP 解算；
- 建立相机、云台和目标坐标系约定；
- 完成目标距离、方向和 yaw/pitch 计算；
- 先用离线图像、合成观测或模拟下位机验证静态目标解算和目标角计算；
- 将云台控制输出接入可记录的模拟 sink，保留后续真实云台适配接口。

坐标轴方向、角度正负、外参获取方式和参数文件格式，先依据规则、协议和参考项目建立可配置约定；真实标定和云台方向确认属于最终统一现场测试。

### 阶段六：跟踪、预测与弹道处理

计划范围：

- 建立目标选择和连续跟踪；
- 针对原地旋转目标估计角度和角速度；
- 根据下位机回传的弹丸速度进行弹道或瞄准补偿；
- 逐步处理图像、计算、通信、云台和飞行时间延迟；
- 用离线、录制或合成数据验证预测结果；真实相机和真实云台的非发射验证留到最终统一现场测试。

跟踪器类型、状态量、滤波参数、延迟模型和弹道模型不在当前规划阶段锁死，优先依据参考项目已有实现和实际数据选择最小可用方案。

### 阶段七：主循环与安全决策

**状态：软件基础版本已完成；现场设备适配和最终运行观测仍属于阶段八。**

本阶段实际完成范围：

- 通过 `AutoAimRuntime` 串联帧输入、检测回调、阶段六垂直管线和正式 CDC 传输；
- 通过 `SafetyController` 建立 `safe`、`aiming`、`fire_ready` 状态及目标、通信、图像、处理、弹速和时间戳安全门；
- 有效瞄准结果转换为正式协议 ID1 的角度制 yaw/pitch；无效状态归零；
- 默认关闭视觉开火，并确保默认和异常路径保持 `fire_flag=0`；
- 退出前同步尝试发送安全命令并停止传输线程；
- 用伪终端、离线图片、合成状态和合成检测结果完成闭环自动化测试。

阶段边界：当前不绑定海康 MVS 专用输入，不假设真实相机标定、云台方向、现场弹速或机械限位结果；真实 USB CDC、现场 NUC、云台、标定和发射操作统一留到阶段八并按 `questions.md` 执行。阶段七的 `allow_visual_fire` 仍是显式配置门，不代表已经获得现场发射许可。

### 阶段八：集成验证与交付准备

**状态：第二轮完成；离线回放、标定文件和现场适配仍待后续轮次。**

前两轮实际完成：

- 建立 `srm_auto_aim_app` 命令行运行入口；
- 支持图片、视频和 OpenCV camera index 输入模式；
- 支持 CDC 设备、传输周期、内参、循环、最大帧数和 dry-run 配置；
- 增加 CSV 运行日志，记录帧、跟踪、瞄准、安全原因和错误；
- 通过离线图片 smoke test 验证入口、检测、EOF、安全回退和日志输出；
- 增加应用参数和日志单元测试，并保持正式协议和阶段七安全边界不变；
- 增加简单 `key=value` 参数文件，支持配置文件先加载、命令行覆盖和未知键拒绝；
- 通过配置文件离线 smoke test 验证输入、dry-run、内参和日志路径生效。

后续仍保留空间：

- 将当前运行参数文件扩展为可审查的标定/完整参数格式，但不在现场事实未确认前锁死格式；
- 增加离线视频回放结果导出和检测图像诊断；
- 根据现场 NUC、MVS SDK 和真实 CDC 行为补充适配；
- 再由用户依据 `questions.md` 集中执行真实设备、云台、标定和必要的发射验证；
- 根据现场数据调整参数并完善最终交付文档。

真实车辆、相机、下位机、标定板、弹丸或安全员参与的具体操作全部以 `questions.md` 为准，不分散到前面的开发阶段。

## 4. 每个阶段的通用完成条件

除非后续另有约定，每个阶段至少应满足：

1. 明确本阶段输入、输出和不负责的内容；
2. 能在无硬件条件下完成的部分有自动化测试或离线验证；
3. 关键失败情况有日志或可观测结果；
4. 不破坏前面阶段已有的测试；
5. 已记录当前假设、限制和未解决问题；
6. 本阶段实际完成后更新 `dev_log/`；
7. 若软件开发发现需要现场确认的事项，只记录到 `questions.md` 并保留配置/接口适配空间；不把现场测试提前为本阶段完成条件，也不把未执行的现场结果写成已完成。

## 5. 当前开发位置与下一步

当前已完成基础版本：

- 第一阶段工程基础与正式协议；
- 第二阶段 CDC 传输层及伪终端验证；
- 第三阶段通用离线/OpenCV 输入抽象；
- 第四阶段传统视觉装甲板检测基线；
- 第五阶段装甲板 PnP 与静态几何解算；
- 第六阶段的逐帧检测结果组合和单帧目标选择基础；
- 第六阶段的最小跨帧状态、角度展开、差分速度和短时预测基础；
- 第六阶段的预测候选关联、噪声/遮挡合成验证基础；
- 第六阶段的无空气阻力基础弹道、飞行时间和额外延迟补偿接口；
- 第六阶段的选择、跟踪、预测和补偿垂直组合接口及合成序列验收。

**阶段六：跟踪、预测与弹道处理——软件基础版本已完成。** 当前完成的是规则和协议约束下的可验证基础切片：传统检测候选经过 PnP、单帧选择、跨帧跟踪、预测关联、弹道/延迟补偿，并通过合成数据自动化验证。它不代表最终目标身份、滤波器、空气阻力模型、现场弹道参数或实时主循环已经完成。后续阶段如发现离线数据不足，可在不破坏接口的前提下继续增强阶段六模块，但当前开发主线进入阶段七。

**阶段七：主循环与安全决策——软件基础版本已完成。** 当前已在离线/模拟环境中串联帧输入、阶段六垂直接口和正式 CDC 传输层，并通过安全状态机保证默认及异常路径 `fire_flag=0`。阶段八已完成前两轮的命令行入口、CSV 运行日志和简单参数文件基础，后续继续完善离线回放、标定配置和现场适配；真实设备测试仍不是开发轮次的前置条件。
