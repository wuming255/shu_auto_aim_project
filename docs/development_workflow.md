# 开发与验证流程

## 轮次范围

每轮只完成一个可验证的软件垂直切片。轮次开始先检查规则、协议和参考项目中是否已有可复用实现，轮次结束必须更新 `dev_log/`。

开发阶段默认使用规则和正式协议、参考项目、本地依赖、模拟输入、伪终端、离线图片/视频和录制数据推进，不要求每轮结束后进行现场或实车调试。项目主体完成后，再集中执行根目录 `questions.md` 中的现场测试。

## 标准命令

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

## 开发阶段验收要求

- 协议模块：单元测试通过，长度和字段布局与正式文档一致。
- 串口模块：使用伪终端或模拟字节流验证拆包、粘包、重连和停止行为，不把真实下位机连接作为每轮验收条件。
- 视觉模块：优先使用图片、视频、录制数据或合成数据进行离线验证，不把真实相机连接作为每轮验收条件。
- 决策和发射模块：先验证安全状态机、断链保护、目标丢失保护和 `fire_flag=0` 默认行为。

## 最终现场验证时机

真实 NUC、海康相机、比赛下位机、云台、标定板和弹丸相关测试，统一安排在软件主体开发完成，并通过本地自动化、离线回放和模拟通信验证之后。具体现场步骤、安全前提和需要用户操作的项目只记录在根目录 `questions.md`。

## 日志要求

日志必须基于实际执行记录，包含：完成内容、命令和结果、问题、未解决事项、下一轮计划。不能把计划或预期结果写成已完成事实。

## 通信层开发验证

通信层开发阶段优先使用 Linux 伪终端进行测试，不直接依赖现场下位机。测试应验证：

- 设备已存在时自动打开并持续发送完整帧；
- 默认命令的 `fire_flag` 为 0；
- 下位机帧按任意拆分后仍可被接收；
- 设备启动晚于程序时后台重连；
- 停止 transport 后线程能够在有限 IO 超时时间内退出。

USB CDC 不依赖传统波特率；当前串口库保留 115200 作为打开设备所需的兼容配置值，不将其当作协议语义。真实 USB CDC 行为在软件主体完成后的统一现场测试阶段确认。
