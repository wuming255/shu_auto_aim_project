# 开发与验证流程

## 轮次范围

每轮只完成一个可验证的软件垂直切片。轮次开始先检查规则、协议和参考项目中是否已有可复用实现，轮次结束必须更新 `dev_log/`。

开发阶段默认使用规则和正式协议、参考项目、本地依赖、模拟输入、伪终端、离线图片/视频和录制数据推进，不要求每轮结束后进行现场或实车调试。项目主体完成后，再集中执行根目录 `questions.md` 中的现场测试。

## 标准命令

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

## 开发阶段验收要求

- 协议模块：单元测试通过，长度和字段布局与正式文档一致。
- 串口模块：使用伪终端或模拟字节流验证拆包、粘包、重连和停止行为，不把真实下位机连接作为每轮验收条件。
- 视觉模块：优先使用图片、视频、录制数据或合成数据进行离线验证，不把真实相机连接作为每轮验收条件。
- 决策和发射模块：先验证安全状态机、断链保护、目标丢失保护和 `fire_flag=0` 默认行为。

## 输入层开发验证

输入层开发阶段应至少验证：

- 单张图片能够读取为 BGR 图像；
- 图片 EOF 和 reset 行为明确；
- 循环图片输入不会破坏序号和时间戳单调性；
- 视频文件和 OpenCV camera index 使用统一接口；
- 采集参数通过配置传入，不在算法代码中写死；
- 没有现场相机时仍可使用图片、视频或模拟数据运行后续模块。

## 最终现场验证时机

真实 NUC、海康相机、比赛下位机、云台、标定板和弹丸相关测试，统一安排在软件主体开发完成，并通过本地自动化、离线回放和模拟通信验证之后。具体现场步骤、安全前提和需要用户操作的项目只记录在根目录 `questions.md`。本轮输入层只实现了通用 OpenCV/离线入口，没有进行真实相机测试。

## 日志要求

日志必须基于实际执行记录，包含：完成内容、命令和结果、问题、未解决事项、下一轮计划。不能把计划或预期结果写成已完成事实。

## 通信层开发验证

通信层开发阶段优先使用 Linux 伪终端进行测试，不直接依赖现场下位机。测试应验证：

- 设备已存在时自动打开并持续发送完整帧；
- 默认命令的 `fire_flag` 为 0；
- 下位机帧按任意拆分后仍可被接收；
- 设备启动晚于程序时后台重连；
- 停止 transport 后线程能够在有限 IO 超时时间内退出。

USB CDC 不依赖传统波特率；当前串口库保留 115200 作为打开设备所需的兼容配置值，不将其当作协议语义。真实 USB CDC 行为在软件主体完成后的统一现场测试阶段确认。

## 传统检测层开发验证

传统检测开发阶段至少使用程序生成图像、离线图片或视频验证：

- 灯条亮度阈值和红/蓝颜色分类；
- 灯条长度、宽高比和角度筛选；
- 同色灯条配对；
- 装甲板几何比值和矩形误差筛选；
- 四个检测点的固定顺序；
- 越界、空图和非法配置处理；
- debug 绘制不依赖 GUI 窗口。

真实装甲板图像采集属于最终现场验证，不能把本地合成图测试结果等同于现场检测效果。

## 几何解算层开发验证

几何解算开发阶段使用已知相机内参和合成目标姿态验证：

- 规则给定装甲板尺寸用于物点建模；
- 四点顺序与检测层保持一致；
- PnP 结果具有正深度；
- 重投影误差可计算并受配置上限约束；
- 相机到云台外参的旋转和平移变换正确；
- yaw/pitch 的单位和坐标约定明确；
- 空间姿态、相机内参、外参和像素点异常时可控失败。

合成数据只能验证数学接口和实现一致性，不能替代最终现场标定和云台方向测试。

## 检测结果组合与目标选择开发验证

目标选择基础层开发阶段应至少验证：

- 每个装甲板候选都保留其原始检测下标、帧序号和时间戳；
- PnP 有效候选能够进入选择，解算失败候选不会阻塞同帧其他候选；
- 默认选择规则在多个有效候选间具有确定性，并优先选择更接近当前云台零位的候选；
- 可选颜色过滤和距离、角度、重投影误差质量门限生效；
- 空检测、全无效检测和非法配置会得到明确的无目标结果；
- 该层不产生跟踪状态、预测结果或非零 `fire_flag`。

上述验证使用合成投影和自动化测试完成；真实装甲板图像、相机标定、云台方向和实车行为仍只在项目主体完成后的 `questions.md` 现场测试阶段确认。

## 跨帧跟踪与预测开发验证

跟踪基础层开发阶段应至少验证：

- 首次有效观测进入 `detecting`，达到确认数量后进入 `tracking`；
- yaw 跨越 `-pi/pi` 时按最短角差展开，角速度估计不出现约 `2*pi/dt` 的假峰；
- pitch、距离和 yaw 速度差分以及可配置平滑系数生效；
- 丢帧外推只在状态、时间戳和速度有效时输出；速度尚未建立但当前帧有效时只能使用零前视当前测量；
- 单帧无目标进入 `temporarily_lost`，连续丢失超限回到 `lost`；
- 时间戳倒退、时间间隔过大和超限角速度会重置或拒绝速度预测；
- 跟踪模块不生成云台通信帧和非零 `fire_flag`。

本阶段使用带已知角速度、丢帧和跨角度边界的合成序列进行自动化验证。真实目标转速、相机时间延迟、云台反馈和弹道参数仍不能由合成测试替代，统一留到项目主体完成后的 `questions.md` 现场测试阶段。

## 多候选预测关联开发验证

预测关联扩展至少应验证：

- 单帧选择器偏向视轴干扰目标时，跟踪器仍能在关联门限内选择与历史运动连续的候选；
- 角度带小幅噪声时，目标检测下标可以在候选列表变化后保持连续；
- 单帧遮挡后，目标在预测位置附近重新出现时能够恢复；
- 无关候选超出角度或距离门限时按丢失处理，不强行切换目标；
- 关闭预测关联后，行为明确退化为使用单帧选择器的已选候选；
- 预测年龄超过 `max_prediction_age_seconds` 后不继续使用陈旧速度进行关联外推。

上述测试仍使用合成观测，不将目标 ID、实际转速、遮挡恢复率或现场参数视为已验证结果。

## 弹道与延迟补偿开发验证

补偿层开发阶段应至少验证：

- 正式协议 `bullet_speed` 以 m/s 传入，弹速低于/高于配置范围时返回 invalid；
- 关闭重力补偿时输出视线角和几何飞行时间，便于隔离检查；
- 开启重力补偿时，解析结果代入抛体轨迹方程能够回到合成目标高度；
- 目标运动速度和额外延迟能够影响 yaw/pitch 前视，并通过迭代保持飞行时间与目标位置一致；
- 弹道不可达、目标距离异常、飞行时间超限、目标状态非 tracking 或预测无效时不输出有效瞄准结果；
- 现场未知的空气阻力、机械偏置和真实发射延迟不得在开发阶段擅自写死；
- 补偿层不生成通信帧、不改变 `fire_flag`。

本轮仅使用数学和合成数据验证，不代表真实弹道、实际弹速和命中率已经完成标定；这些内容统一按照 `questions.md` 的最终现场流程执行。
