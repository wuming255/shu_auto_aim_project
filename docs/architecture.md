# 软件架构

## 分层

```text
相机输入
  -> 感知层：灯条/装甲板检测、颜色和几何筛选
  -> 解算层：PnP、坐标变换、相机-云台外参
  -> 估计层：目标选择、跟踪、旋转状态预测
  -> 决策层：弹道、瞄准点、稳定性和开火请求
  -> 通信层：USB CDC 正式协议
  -> 下位机：云台控制、火控和人工许可
```

## 当前已实现的基础层

- `src/protocol/`：正式自瞄协议编码、解码和流式解析。
- `src/io/self_aim_transport.*`：正式协议串口收发、后台线程和重连。
- `src/io/frame_source.*`：图片、视频和 OpenCV camera index 输入抽象，统一输出 BGR 图像、单调时间戳、序号和文件源时间。
- `tests/`：协议、传输层伪终端和输入抽象测试。

本阶段的输入抽象不绑定海康 MVS SDK，现场工业相机适配器后续在相同的帧接口上接入。第一轮不复制参考项目完整视觉业务，避免把参考项目旧通信协议和不必要的兵种逻辑带入本项目。

## 复用策略

优先顺序为：

1. 直接复用已有实现；
2. 小幅修改以匹配本项目接口和规则；
3. 重构后复用；
4. 仅在没有可用实现或存在明确技术冲突时重新实现。

参考项目的相机驱动、传统检测、PnP、跟踪、弹道、日志和标定工具可作为后续候选复用对象；其旧通信模块只复用线程、重连和状态管理思路，不复用报文结构。

## 安全边界

- 协议层不自动产生非零 `fire_flag`。
- 决策层只有在目标、解算、通信和云台状态均有效时才可生成开火请求。
- 任何失联、超时、数据异常或目标丢失都必须回到非开火状态。

## 输入层（第三轮基础版本）

- 直接复用参考项目 `CameraBase` 的“图像 + 时间戳”接口思想，并重构为不依赖 YAML、日志和厂商 SDK 的独立 `FrameSource`。
- 当前支持单张图片、视频文件和 OpenCV camera index；文件输入支持 EOF、循环读取和 reset。
- 读取结果统一为 BGR `cv::Mat`，同时提供单调递增的 `steady_clock` 时间戳、序号和可用的源时间。
- OpenCV 的宽度、高度、帧率和 backend 作为配置项，不写死现场设备参数。
- 海康 CS016/MVS 适配器未在本轮直接绑定，真实硬件验证统一留到软件主体完成后的 `questions.md` 现场测试阶段。

## 通信传输层（第二轮）

- `src/io/self_aim_transport.hpp/.cpp`：管理正式 CDC 协议的串口收发、设备打开、有限超时、后台接收/发送线程、最新下位机状态和重连。
- `src/third_party/serial/`：直接复用参考项目中 MIT 许可的跨平台 serial 实现；本项目当前只编译 Linux Unix 后端。
- 接收线程以固定大小块读取并交给 `IncomingStreamParser`，不依赖 USB 包边界。
- 发送线程按配置周期发送完整 ID1+ID2 帧；默认命令初始化为 `fire_flag=0`。
- 设备文件暂时不存在时，构造 transport 不打开设备，由后台线程按重连间隔尝试打开，支持设备晚出现。
- 伪终端测试验证了启动、初始非开火帧、拆分下位机帧、状态读取和设备晚出现重连。

## 传统检测层（第四轮基础版本）

- `src/vision/traditional_detector.*`：从 BGR 图像提取高亮区域，筛选近竖直灯条，按颜色配对灯条并输出装甲板候选。
- 几何字段和点顺序参考 `sp_vision_25-main/tasks/auto_aim/armor.*` 与 `detector.*`，保留左上、右上、右下、左下四点顺序，便于后续 PnP 接入。
- 本实现将参考项目的灰度阈值改为 BGR 三通道最大值阈值，避免纯红/纯蓝灯条灰度化后亮度不足；颜色差阈值和几何阈值均可配置。
- 检测层不在本轮绑定数字分类器、OpenVINO 或具体赛场图像；`ArmorObservation` 只描述灯条/几何候选，目标命名和跟踪在后续模块处理。
- `draw_debug()` 只返回绘制后的图像，不打开窗口，适合无桌面环境和离线回放。

## 几何解算层（第五轮基础版本）

- `src/vision/pose_solver.*`：把传统检测层输出的四个像素角点转换为装甲板在相机坐标系和云台坐标系中的位置。
- PnP 物点尺寸以校内赛规则的 `140 × 125 mm` 为默认值，不沿用参考项目旧版大小装甲板尺寸；尺寸仍可配置以便后续根据正式靶标定义调整。
- 输入角点顺序固定为 `TL, TR, BR, BL`，与检测层和后续解算接口保持一致。
- 对平面装甲板使用 OpenCV IPPE，并在多个候选姿态中选择正深度且重投影误差较小的解。
- 输出相机/云台坐标、距离、yaw/pitch（弧度和角度）及重投影 RMS；当前只计算目标几何角，不生成通信命令。
- 相机内参、畸变、相机到云台旋转和平移均为配置数据；默认外参只用于接口和合成测试，不代表现场标定结果。
- 真实标定、坐标轴方向和云台角度正负确认仍属于最终 `questions.md` 现场验证范围。

## 检测结果组合与目标选择层（第六轮基础版本）

- `src/vision/target_selector.*` 将 `DetectionResult::armors` 的逐帧候选与 `ArmorPoseSolver` 组合，生成带有帧序号、单调时间戳、原始检测下标、装甲板观测和 `PoseSolution` 的 `TargetObservation`。
- `TargetSelection` 保留本帧所有候选，包括 PnP 失败候选，便于离线诊断；只有通过 PnP、颜色（如启用）和距离/角度/重投影质量门限的候选才会被选中。
- 当前选择层没有数字分类和跨帧状态，因此选择策略是：在有效候选中优先选择云台 yaw/pitch 到零位的二维角距离最小者，再按重投影误差、距离和原始检测顺序稳定打破平局。该策略只作为单帧基础，不等同于最终目标身份或旋转预测。
- 单个检测候选输入异常会被隔离成 `pose.valid=false` 的诊断记录，不使同帧其他候选整体失败。
- 本轮仍不生成云台通信命令、不估计角速度、不进行弹道补偿，也不改变 `fire_flag` 安全边界。

## 跨帧跟踪与短时预测层（第七轮基础版本）

- `src/vision/target_tracker.*` 接收 `TargetSelection` 的当前已选观测和当前帧时间戳，维护单目标的最小跨帧状态。
- 跟踪状态明确分为 `lost`、`detecting`、`tracking` 和 `temporarily_lost`；连续有效观测数、连续丢失帧数和时间间隔均有配置化状态门限。
- yaw 使用最短角差展开，避免目标角跨越 `-pi/pi` 时产生虚假的大速度；pitch、距离使用带可配置平滑系数的一阶差分估计。
- 在速度有效且状态未超时的情况下，输出配置前视时间的短时外推；时间戳异常、连续丢失超限或速度异常时不输出丢帧外推。仍有当前有效测量但速度尚未建立时，`prediction_valid` 仅表示当前测量的零前视回退值。
- 本轮跟踪只消费单帧选择器已经选出的候选，不做数字身份识别、多候选跨帧关联或复杂 EKF；这些需要真实/离线序列后再决定是否引入。
- 跟踪层不生成通信帧和 `fire_flag`，任何后续开火决策仍必须经过独立安全门。
