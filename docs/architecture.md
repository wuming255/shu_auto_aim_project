# 软件架构

## 分层

```text
相机输入
  -> 感知层：灯条/装甲板检测、颜色和几何筛选
  -> 解算层：PnP、坐标变换、相机-云台外参
  -> 估计层：目标选择、跟踪、旋转状态预测
  -> 决策层：弹道、瞄准点、稳定性和开火请求
  -> 通信层：USB CDC 正式协议
  -> 下位机：云台控制、火控和人工许可
```

## 当前已实现的基础层

- `src/protocol/`：正式自瞄协议编码、解码和流式解析。
- `src/io/self_aim_transport.*`：正式协议串口收发、后台线程和重连。
- `src/io/frame_source.*`：图片、视频、OpenCV camera index 和可选 MVS USB 输入抽象，统一输出自有 BGR 图像、单调时间戳、序号、文件源时间和处理后方向。
- `src/io/image_geometry.*`：输入旋转、尺寸/方向元数据和无覆盖 YAML 发布。
- `src/vision/camera_calibration.*`：棋盘格内参求解、完整 K/畸变与相机到云台 R/t 加载校验。
- `src/io/mvs_camera.*`：SDK 按需动态加载、生命周期、USB 枚举/选择、节点查询/设置、借帧/转换/归还；厂商头文件与句柄封装在 PImpl 中。
- `src/app/`：命令行运行入口、配置文件、CSV 运行日志、运行统计、debug 图像和离线 smoke test 入口。
- `tests/`：协议、传输层伪终端、输入抽象、阶段七闭环和应用支持测试。

MVS 适配器已通过相同帧接口接入，编译支持和运行库均可选，离线输入不调用 SDK；真实硬件与完整 SDK ABI 匹配仍按 `questions.md` 确认。参考项目只复用适合当前接口的采集调用流程和通用思路。

## 复用策略

优先顺序为：

1. 直接复用已有实现；
2. 小幅修改以匹配本项目接口和规则；
3. 重构后复用；
4. 仅在没有可用实现或存在明确技术冲突时重新实现。

参考项目的相机驱动、传统检测、PnP、跟踪、弹道、日志和标定工具可作为后续候选复用对象；其旧通信模块只复用线程、重连和状态管理思路，不复用报文结构。

## 安全边界

- 协议层不自动产生非零 `fire_flag`。
- 决策层只有在目标、解算、通信和云台状态均有效时才可生成开火请求。
- 任何失联、超时、数据异常或目标丢失都必须回到非开火状态。

## 输入层（第三轮基础与第十七轮 MVS 扩展）

- 直接复用参考项目 `CameraBase` 的“图像 + 时间戳”接口思想，并重构为不依赖 YAML、日志和厂商 SDK 的独立 `FrameSource`。
- 当前支持单张图片、视频文件、OpenCV camera index 和可选 MVS USB；文件输入支持 EOF、循环读取和 reset。
- 读取结果统一为 BGR `cv::Mat`，同时提供单调递增的 `steady_clock` 时间戳、序号和可用的源时间。
- OpenCV 的宽度、高度、帧率和 backend 作为配置项，不写死现场设备参数。
- MVS 按序列号/索引选设备，默认仅在一台 USB 相机时自动选择；生命周期使用 RAII 管理初始化、打开、取流、缓冲释放、停止和销毁。
- 未指定曝光、增益、尺寸、FPS、像素格式时不改对应设备节点；连续取流显式保证触发关闭。节点参数验证范围/增量、读写权限并读回，查询模式不改参数、不取流。
- MVS 帧在借到 SDK 缓冲时记录主机时间，复制或转换成自有 BGR 后归还缓冲；实时失败提供具体诊断且不是文件 EOF。应用通过现有读帧失败安全路径退出，当前不提供相机重连或已验证的最新帧保证。
- SDK 编译/运行环境和旧参考头文件回退限制见 `docs/deployment.md`；真实硬件验证统一留到 `questions.md` 现场阶段。

## 通信传输层（第二轮）

- `src/io/self_aim_transport.hpp/.cpp`：管理正式 CDC 协议的串口收发、设备打开、有限超时、后台接收/发送线程、最新下位机状态和重连。
- `src/third_party/serial/`：直接复用参考项目中 MIT 许可的跨平台 serial 实现；本项目当前只编译 Linux Unix 后端。
- 接收线程以固定大小块读取并交给 `IncomingStreamParser`，不依赖 USB 包边界。
- 发送线程按配置周期发送完整 ID1+ID2 帧；默认命令初始化为 `fire_flag=0`。
- 设备文件暂时不存在时，构造 transport 不打开设备，由后台线程按重连间隔尝试打开，支持设备晚出现。
- 伪终端测试验证了启动、初始非开火帧、拆分下位机帧、状态读取和设备晚出现重连。

## 传统检测层（第四轮基础版本）

- `src/vision/traditional_detector.*`：从 BGR 图像提取高亮区域，筛选近竖直灯条，按颜色配对灯条并输出装甲板候选。
- 几何字段和点顺序参考 `sp_vision_25-main/tasks/auto_aim/armor.*` 与 `detector.*`，保留左上、右上、右下、左下四点顺序，便于后续 PnP 接入。
- 本实现将参考项目的灰度阈值改为 BGR 三通道最大值阈值，避免纯红/纯蓝灯条灰度化后亮度不足；颜色差阈值和几何阈值均可配置。
- 检测层不在本轮绑定数字分类器、OpenVINO 或具体赛场图像；`ArmorObservation` 只描述灯条/几何候选，目标命名和跟踪在后续模块处理。
- `draw_debug()` 只返回绘制后的图像，不打开窗口，适合无桌面环境和离线回放。

## 几何解算层（第五轮基础版本）

- `src/vision/pose_solver.*`：把传统检测层输出的四个像素角点转换为装甲板在相机坐标系和云台坐标系中的位置。
- PnP 物点尺寸以校内赛规则的 `140 × 125 mm` 为默认值，不沿用参考项目旧版大小装甲板尺寸；尺寸仍可配置以便后续根据正式靶标定义调整。
- 输入角点顺序固定为 `TL, TR, BR, BL`，与检测层和后续解算接口保持一致。
- 对平面装甲板使用 OpenCV IPPE，并在多个候选姿态中选择正深度且重投影误差较小的解。
- 输出相机/云台坐标、距离、yaw/pitch（弧度和角度）及重投影 RMS；当前只计算目标几何角，不生成通信命令。
- 相机内参、畸变、相机到云台旋转和平移均为配置数据；默认外参只用于接口和合成测试，不代表现场标定结果。
- 真实标定、坐标轴方向和云台角度正负确认仍属于最终 `questions.md` 现场验证范围。

## 检测结果组合与目标选择层（第六轮基础版本）

- `src/vision/target_selector.*` 将 `DetectionResult::armors` 的逐帧候选与 `ArmorPoseSolver` 组合，生成带有帧序号、单调时间戳、原始检测下标、装甲板观测和 `PoseSolution` 的 `TargetObservation`。
- `TargetSelection` 保留本帧所有候选，包括 PnP 失败候选，便于离线诊断；只有通过 PnP、颜色（如启用）和距离/角度/重投影质量门限的候选才会被选中。
- 当前选择层没有数字分类和跨帧状态，因此选择策略是：在有效候选中优先选择云台 yaw/pitch 到零位的二维角距离最小者，再按重投影误差、距离和原始检测顺序稳定打破平局。该策略只作为单帧基础，不等同于最终目标身份或旋转预测。
- 单个检测候选输入异常会被隔离成 `pose.valid=false` 的诊断记录，不使同帧其他候选整体失败。
- 本轮仍不生成云台通信命令、不估计角速度、不进行弹道补偿，也不改变 `fire_flag` 安全边界。

## 跨帧跟踪与短时预测层（第七轮基础版本）

- `src/vision/target_tracker.*` 接收 `TargetSelection` 的当前已选观测和当前帧时间戳，维护单目标的最小跨帧状态。
- 跟踪状态明确分为 `lost`、`detecting`、`tracking` 和 `temporarily_lost`；连续有效观测数、连续丢失帧数和时间间隔均有配置化状态门限。
- yaw 使用最短角差展开，避免目标角跨越 `-pi/pi` 时产生虚假的大速度；pitch、距离使用带可配置平滑系数的一阶差分估计。
- 在速度有效且状态未超时的情况下，输出配置前视时间的短时外推；时间戳异常、连续丢失超限或速度异常时不输出丢帧外推。仍有当前有效测量但速度尚未建立时，`prediction_valid` 仅表示当前测量的零前视回退值。
- 本轮跟踪只消费单帧选择器已经选出的候选，不做数字身份识别、多候选跨帧关联或复杂 EKF；这些需要真实/离线序列后再决定是否引入。
- 跟踪层不生成通信帧和 `fire_flag`，任何后续开火决策仍必须经过独立安全门。

## 预测候选关联扩展（第八轮基础版本）

- 当已有跟踪状态时，`TargetTracker` 不再盲目接受 `TargetSelection` 的单帧首选项，而是在 `TargetSelection::observations` 的所有有效候选中，按当前时刻的预测 yaw/pitch/range 计算关联误差。
- 关联默认优先使用当前跟踪状态的预测位置；可通过 `use_prediction_association` 关闭，退化为直接接受单帧选择器的已选候选。
- `max_association_angular_error_rad` 和 `max_association_range_error_m` 提供独立关联门限。没有候选通过门限时按目标丢失处理，不把远处无关候选强行当作当前目标。
- 关联使用的速度外推也受 `max_prediction_age_seconds` 约束；状态过旧时不继续使用陈旧速度外推。
- 本轮用带小幅角度噪声、单帧遮挡、视轴干扰候选和重新捕获的合成序列验证关联行为；仍不代表真实图像中的目标身份识别或最终跟踪参数。

## 弹道与延迟补偿层（第九轮基础版本）

- `src/control/aim_compensator.*` 接收 `TargetTrackEstimate` 和正式协议下位机回传的 `bullet_speed`，输出独立于通信协议的 yaw/pitch 瞄准结果。
- 基础模型采用可配置的恒定重力、无空气阻力点目标模型；参考项目已有 `tools::Trajectory` 的解析弹道和飞行时间迭代思路，但其 Eigen/YAML/完整兵种目标模型与当前工程不兼容，因此本轮只复用数学路线并重构为当前接口。
- 解算先把目标的球坐标估计转换为水平距离和竖直高度，再求低弹道解；若目标超出弹道包络、弹速异常、距离异常或飞行时间超限，则返回 invalid，不生成任何通信命令。
- 跟踪器已有的 prediction horizon 不会在补偿器中重复添加；`additional_latency_seconds` 只表示尚未在跟踪器中建模的额外延迟。补偿器迭代求解目标运动和弹丸飞行时间的耦合关系。
- 当前输出包含规范化 yaw、重力补偿后的 pitch、视线 pitch、补偿量、飞行时间和总前视时间；该层不决定是否开火，默认不产生 `fire_flag`。
- 实际弹速含义、发射延迟、机械 pitch 偏置、空气阻力和现场命中偏差必须在项目主体完成后的 `questions.md` 统一现场测试中确认，不能用本地合成测试替代。

## 阶段六垂直组合接口（第十轮基础版本）

- `src/control/auto_aim_pipeline.*` 将阶段六已经完成的 PoseSolver、TargetSelector、TargetTracker 和 AimCompensator 串成一个无硬件依赖的单帧接口。
- 每次 `process()` 输入一帧 `DetectionResult`、时间戳、帧序号和协议层提供的 `bullet_speed`，输出本帧候选、跟踪状态和数学瞄准结果。
- 该接口不负责相机读取、不负责 CDC 收发、不负责云台命令、不负责 `fire_flag` 或安全许可；这些内容属于后续阶段七主循环与安全决策层。
- 合成旋转序列已覆盖：PnP 逐帧解算、视轴干扰候选、预测关联、跟踪确认、弹道补偿、单帧遮挡、重新捕获和异常弹速。
- 阶段六的“跟踪、预测与弹道处理”软件垂直切片至此具备可自动化验证的组合接口；当前数学参数和检测算法仍不是现场标定结果。

## 主循环与安全决策层（第七阶段基础版本）

- `src/control/auto_aim_runtime.*` 负责把 `FrameSource`、检测回调、`AutoAimPipeline`、`SafetyController` 和 `SelfAimTransport` 串成单步/持续运行接口。
- 每次 `step()` 读取一帧并保存帧时间戳，读取当前下位机状态和 `bullet_speed`，调用检测与阶段六垂直管线，再由安全控制器决定是否输出 yaw/pitch；安全决策时刻在帧读取和处理之后取得，避免新帧因时间采样顺序被误判为未来帧。
- `SafetyController` 的基础状态为 `safe`、`aiming`、`fire_ready`。只有通信运行且已连接、帧和下位机状态未过期、处理成功、目标处于 `tracking`、瞄准有效、传输状态中的 `bullet_speed` 和数学结果中的 `bullet_speed` 均在配置范围内时，才允许输出有效 yaw/pitch。
- 默认 `allow_visual_fire=false`，所有异常路径和默认路径的 `fire_flag` 均为 0。即使调用方提供视觉开火意图，默认配置也只记录 `fire_disabled`，不会生成非零开火请求；显式开启该配置仍不绕过下位机火控和人工许可。
- 无效状态下 yaw/pitch 归零并保持 `fire_flag=0`；安全原因以枚举和摘要字符串返回，便于后续运行日志和离线诊断。
- `SelfAimTransport::latest_state_timestamp()` 记录最近完整下位机状态帧的单调时间；断链时清除旧状态，避免快速重连且尚未收到新状态时复用旧弹速。
- `SelfAimTransport::send_command_now()` 用于退出前同步尝试发送确定的安全帧，然后再停止传输线程；周期发送仍由传输线程按正式 CDC 协议执行。
- 阶段七测试使用 Linux 伪终端、合成下位机状态帧、离线图片输入和合成检测结果，验证了闭环 yaw/pitch 输出、目标丢失、状态过期、EOF、生命周期停止以及全程 `fire_flag=0`。MVS 扩展复用这套运行时与安全逻辑；未进行真实云台或发射测试。


## 运行入口与可观测性（阶段八第一轮）

- `src/app/application_options.*` 将输入类型、文件/相机来源、CDC 设备、传输周期、内参、循环、最大帧数和 dry-run 模式解析为可验证配置；不把真实标定值写死在代码中。
- `src/app/runtime_csv_logger.*` 记录帧序号、帧源时间、候选数量、跟踪状态、数学瞄准结果、安全状态、`fire_flag`、安全原因和错误信息，支持无桌面环境下的离线诊断。
- `src/app/main.cpp` 使用现有 `TraditionalDetector` 和阶段六/七模块建立 `srm_auto_aim_app`；图片、视频、OpenCV camera index 和 MVS 共用同一运行路径。MVS 枚举/参数查询在创建 transport 前退出。
- `--dry-run` 不启动传输线程，仅用于输入/检测/日志 smoke test；由于安全控制器会看到 transport 未运行，该模式不会输出有效瞄准命令。
- 当前入口加载完整内参/畸变与显式外参，不修改视觉开火配置；真实标定与 MVS/CDC 现场效果仍由 `questions.md` 验证。


## 参数文件层（阶段八第二轮）

- `src/app/application_options.*` 在命令行参数之上增加简单 `key=value` 配置文件；配置文件先应用，命令行后应用，以便现场脚本保留稳定基础参数并临时覆盖输入、内参或日志路径。
- 配置解析拒绝未知键、缺少等号、非法布尔值、非法数值和缺少图片/视频源，避免拼写错误静默改变运行行为。
- 配置文件只描述上位机运行参数，不承载正式 CDC 帧字段、视觉开火许可、下位机配置或未经确认的现场标定结果。

## 集成验证与运行报告层（阶段八后续轮次）

- `src/app/runtime_statistics.*` 在不改变算法和协议接口的前提下，按 `AutoAimRuntime::step()` 累计输入帧、EOF、处理错误、候选数量、安全状态、处理耗时和 transport 计数。
- `RuntimeStepResult::step_duration` 使用 `steady_clock` 记录从本次 `step()` 开始到安全命令写入 transport 的单调耗时；该值用于诊断，不作为控制时钟或协议字段。
- `RuntimeCsvLogger` 在原有诊断字段基础上追加 `step_duration_us` 和三个累计 `transport_*` 字段；CSV 仍是诊断输出，不作为正式 CDC 输入。
- `srm_auto_aim_app` 可按 `--debug-every` 将 `TraditionalDetector::draw_debug()` 的结果保存到 `--debug-dir`，并按 `--summary` 写出稳定的 key=value 运行摘要。目录创建、图像写入和摘要写入失败会报告错误。
- 当前应用的 debug、CSV 和 summary 输出均可在 `--dry-run` 下使用；未启动 transport 时安全状态保持非开火，摘要中的 `nonzero_fire_request_count` 应为 0。
- 运行统计只用于观测和交付准备，不会改变目标选择、预测、弹道补偿、安全状态机或正式 18 字节/30 字节 CDC 帧布局。真实相机、标定、CDC、云台和发射验证仍统一放在 `questions.md`。

## 可选离线窗口调试

- `src/app/debug_viewer.*` 在应用层显示 `draw_debug()` 图像和 `DetectionResult::brightness_mask`；文件回放管理播放节奏、暂停、单步，实时相机调用一次 `waitKey(10)` 处理 GUI 事件，不进入回放等待循环。`terminal_quit_input.*` 在调试期间读取前台终端退出按键，并恢复终端状态。算法层和输入层不调用 GUI。
- `--show-debug` 默认关闭，仅用于 dry-run；显示每帧，与 debug 文件保存频率独立。文件暂停期间不调用运行时，不重复记日志或录像；实时预览仅接受退出操作。
- HighGUI 只链接到应用窗口实现，CMake 可自动降级为非 GUI 构建或通过 `SRM_ENABLE_GUI=OFF` 禁用。未启用窗口的路径无需桌面显示服务。
- 播放和暂停不改变 `FrameSource` 的单调时间戳定义，窗口回放的检测观察不等同于预测、弹道或现场性能验证。

## 原始 BGR 录像（第十九轮）

- `src/app/video_recorder.*` 为独立应用层 RAII 录像器，使用 OpenCV FFmpeg VideoWriter，默认关闭、仅允许 dry-run。每个成功读取的帧同步写一次；不改动输入层、检测器或运行时协议。
- 输入为 `Frame.bgr`，在绘制检测叠加图前写入；不添加四元数/姿态文本。参考 Recorder 的原图保存用途，CSV 仍单独记录现有运行结果和主机时间。
- 先以独占临时文件存放 AVI，封口后 fsync 并完整解码校验尺寸/帧数，再以同目录硬链接无覆盖发布。异常保留 partial 路径，正常调用显式 `close()` 检查错误，析构提供兜底清理。
- 录像 FPS 是恒定播放元数据，不限速、不插帧、不假设曝光时间；`step_duration_us` 不包含应用层编码、GUI 或退出校验耗时。

## 标定、方向绑定与分层耗时（第二十轮）

- `srm_calibrate_camera` 是离线图片目录/视频入口，复用 `FrameSource` 的处理后 BGR 和方向；显式棋盘格内角点及方格尺寸，亚像素角点、OpenCV 标定、总体/逐视图 RMS，输出候选 YAML 与检查图，无相机/CDC/GUI 调用。
- 参考工具使用对称圆点阵和阻塞窗口，当前仅复用平面物点、标定和重投影流程，适配棋盘格及现有 C++17/OpenCV 接口；不迁移旧通信、姿态记录或额外依赖。
- 相机旋转和文件额外旋转分别配置；录像保存同一处理后 BGR，首帧独占创建 `<录像名>.metadata.yml`。回放读取已有几何，不因相机设置而重复旋转。首帧元数据可能在录像失败后作为诊断保留。
- 完整内参 YAML 的 K、畸变直接注入 `PoseSolverConfig`，每帧校验尺寸/方向；外参明确处理后 OpenCV 相机坐标、云台 x前/y左/z上与米制平移，按 `p_g=R_g_c*p_c+t_g_c` 使用。旧四参数仅供 dry-run；live 缺完整内外参在 transport 启动前拒绝。
- runtime 分别记录读帧、检测及检测后算法管线；应用记录日志、录像、debug 绘制/保存、GUI 显示/等待、整次循环及封口回读。阶段平均/最大耗时与样本数写 summary，原 CSV 21 列保持，外层时长和内部阶段不可叠加当作总量。
- 文件预览剩余等待限制为 1–10 ms，超时不再固定多等 10 ms；暂停仍泵送事件。后续按键排查将相机事件等待改为一次 `waitKey(10)`，以处理 GTK3 快速刷新时按键不返回的问题；没有改变相机节点或采集 FPS，GUI 等待单独计时。
- 本轮仅有合成、离线和模拟 SDK 验证；默认 `allow_visual_fire=false` 且应用不提供视觉开火意图，正式协议与退出安全命令不受标定和诊断功能改变。现场规格、R/t、精度与桌面性能统一记录于 `questions.md`。
