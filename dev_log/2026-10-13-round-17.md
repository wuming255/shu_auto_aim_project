# 第十七轮开发日志：可选海康 MVS USB 输入

日期：2026-10-13

## 本轮目标

为海康 `MV-CS016-10UC` 增加可选 MVS USB 采集，通过已有 `FrameSource` 接入应用，支持枚举、参数查询和显式配置，保留离线图片/视频、OpenCV camera 和窗口调试。开发验收使用模拟 SDK、离线数据和用户提供的真实 Runtime；NUC 相机采集单独按 `questions.md` 验证。

## 分析依据与实现约定

- 用户反馈的 NUC 为 x86_64 Linux，相机 USB `2bdf:0001`、链路 `5000M`，没有 `/dev/video*`，OpenCV camera index 无法打开；存在 `/opt/MVS/lib/64/libMvCameraControl.so.4.7.0.3`，没有 MVS 图形客户端。这些现场事实未在当前开发机重验。
- 参考 `sp_vision_25-main/io/hikrobot/` 的枚举、设备生命周期、借帧、像素转换和缓冲释放流程，按当前接口封装；没有照搬参考项目线程、USB reset、默认第一设备或曝光/增益/150 FPS 配置。
- 用户提供的 `MvCamCtrlSDK_Runtime-4.7.0_x86_64_20251113.tar.gz` 仅解压到 `/tmp/opencode`，未执行安装/环境/tuning 脚本、管理员操作或系统目录修改。包内缺少对应开发头文件、采集示例和完整 API 文档。
- 本地使用参考项目 SDK 头文件回退。实际提供库版本为 `4.7.0.3`，参考项目附带库为 `4.1.2.2`；检查了所用动态符号和库依赖。初始化/结束接口在提供库存在，但旧头文件未声明，以动态函数指针绑定。
- 当前版本门接受 `4.7.x`，只对提供的 `4.7.0.3` 做了真实 Runtime 验证，不能据此确认全部帧结构 ABI。最终部署需提供对应开发 SDK include，重新构建并实机验证。

## 本轮实际完成

- 新增 `src/io/mvs_camera.hpp/.cpp`：PImpl 隔离厂商头文件与句柄，按需 `dlopen`/`dlsym`，检查版本和必需符号，以 RAII 管理 SDK、设备和取流生命周期。
- USB 枚举锁内复制设备描述；支持序列号和索引选择，默认仅在恰好一台 USB 相机时自动选择。枚举/启动报告输出 SDK、加载请求路径、设备数量或选择结果、型号、序列号和 VID:PID。
- 新增 `--list-cameras`、`--camera-info`，两者在创建 transport 前退出。参数查询独占打开设备，不改节点、不启动取流，报告当前值、范围/增量、枚举符号、读写状态和查询错误。
- 新增 MVS 库路径、序列号/索引、宽高、FPS、曝光、增益、像素格式和有限超时的 CLI/config。曝光/增益/像素格式的 `default` 与尺寸/FPS 的 `0` 清除显式覆盖，保留打开时的当前值；增益 `0` 是显式设置。
- 开始采集确保连续模式和触发关闭；其他未指定节点保持当前设置。显式值验证范围、增量、访问模式和读回，参数错误使启动失败；已成功写入的节点不回滚。
- 使用 Linux 支持的一个 SDK 缓存节点，不调用参考头文件标注为 Windows-only 的 `MV_CC_SetGrabStrategy`，不承诺最新帧或自动重连。
- 取帧时记录主机 `steady_clock`。BGR8 复制，其余格式通过 SDK 转为自有 BGR `cv::Mat`；检查元数据、尺寸、丢包、长度和转换输出，成功与异常均归还 SDK 缓冲。限制 BGR 图像为 256 MiB，并在乘 3 前检查像素数，避免大小计算溢出。
- `FrameSource` 新增 MVS 类型和具体 `last_error()`，沿用连续序号、严格递增单调时间戳和自有图像接口；MVS 源时间为 0，实时失败不作为文件 EOF。
- 应用打印 MVS 报告；取流失败进入现有读帧失败安全路径，记录已配置的 CSV/summary，以返回码 1 退出。启动失败仅打印错误，不生成运行摘要。
- CMake 增加 `SRM_ENABLE_MVS` 和外部 `SRM_MVS_INCLUDE_DIR`，输出头文件来源及参考回退限制；不直接链接海康 Runtime。关闭支持或缺头文件时仍可构建离线/OpenCV 入口，MVS 请求明确报不可用。
- 新增模拟 SDK、缺符号库、MVS 后端测试和应用 smoke test；扩展参数/config 和 FrameSource 不可用诊断测试。新增手动真实 Runtime 离线转换程序，不纳入默认 CTest。
- 更新应用、部署、架构、工作流、开发计划和现场清单，提供无需 MVS 图形客户端的 NUC 枚举、查询、dry-run 和现场记录步骤。

## 遇到的问题及处理

1. Runtime 包没有对应开发头文件，旧参考头文件不能证明完整 ABI 匹配。CMake 显示来源和回退限制，部署文档及 `questions.md` 明确记录；此问题尚未解决。
2. 最初离线转换探针使用空句柄，真实 SDK 返回 `0x80000000`。改为只 `CreateHandle` 的合成设备描述后，六种格式转换通过，没有打开真实设备。
3. 参考头文件的 `SetGrabStrategy` 仅标注 Windows 支持。Linux 采集去掉该调用，保留一个缓存节点，不声称最新帧或延迟已经验证。
4. 手动转换测试的 `dlclose` 函数指针 deleter 产生编译警告，改为 lambda 后构建通过；帧大小计算也改为先限制像素数再乘 3。

## 重要限制与下一轮安排

- 软件 MVS 接入、模拟失败安全退出、三种构建配置和真实 Runtime 离线调用已经验证；真实设备/帧结构完整 ABI 尚未确认。
- 下一步是补齐对应 4.7 开发 SDK include，在 NUC 重新构建，按 `questions.md` 保存枚举/参数查询报告，执行 120 帧及持续 dry-run，确认权限、模块、颜色、节点范围、实际 FPS、延迟和断开退出行为。
- 一个缓存节点不代表最新帧；主机取帧时间不是曝光起点，当前没有相机自动重连。参数调整可能部分成功，尺寸/ROI 改变后需核对标定。
- 当前开发机没有真实相机，未执行真实 CDC、云台、标定或发射测试；默认内参和合成数据不作为现场效果证据。
