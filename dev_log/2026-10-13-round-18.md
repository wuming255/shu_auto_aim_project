# 第十八轮开发日志：快捷启动脚本和参数说明

日期：2026-10-13

## 本轮目标与范围

用户希望每次运行不必输入大量参数，并获得可选参数和功能说明。本轮复用已有 `key=value` 配置加载、命令行覆盖和 MVS 查询入口，增加 Bash 启动脚本、默认配置与中文使用说明。

## 实际完成

- 新增根目录 `run.sh`，使用 `bash run.sh` 即可启动；支持 `run`、`video`、`image`、`mvs`、`camera`、`list`、`info`、`app-help` 和脚本中文帮助。
- 新增 `run.conf`，集中配置视频路径、窗口、帧数、日志、相机和 CDC 参数。随附配置默认回放 `demo.avi`、dry-run、最多 120 帧、不开窗口，每 20 帧存一张检测图。
- 配置优先级为配置文件、模式预设、用户追加参数；显式 `--config` 替换默认配置。使用 Bash 数组和 `exec` 保留带空格参数、空字符串、应用退出码与直接信号传递。
- 脚本固定以项目根目录为相对路径基准，可从其他目录调用。`mvs`/`camera` 预设清空文件源，关闭离线窗口、暂停和播放限速，避免继承视频设置。
- 支持 `SRM_APP` 指定已有可执行文件，`MVS_ROOT` 指定已有 SDK 根目录。默认 `/opt/MVS/lib/64` 存在时为子进程补充模块搜索环境；保留显式 `MVCAM_COMMON_RUNENV`，不执行 SDK 安装脚本。
- 输出配置为 `replay_debug/latest/` 下的 CSV、摘要和检测图。说明明确同名文件覆盖、旧图像不自动清理、可通过批次目录保留结果及空值关闭输出。
- 新增 `docs/launcher.md`，列出快捷模式、配置修改示例、全部现有应用选项对应的配置键、窗口按键、MVS 环境、输出和退出行为；应用与部署文档增加入口链接。
- 新增 `tests/launcher_smoke.cmake` 并接入 CTest，验证跨目录路径、含空格路径、自定义配置替换、命令行覆盖、失败返回码；有模拟 SDK 时还验证 list/info 和 MVS 模式清除 GUI 配置。

## 验证与结果

### 1. 测试先行及故障定位

先编写启动验收，再运行：

```bash
cmake -DROOT=/home/wuming/Projects/shu_auto_aim_project \
  -DAPP=/home/wuming/Projects/shu_auto_aim_project/build/srm_auto_aim_app \
  -DOUTPUT_DIR=/tmp/opencode/srm-round18-launcher \
  -P tests/launcher_smoke.cmake
```

脚本尚未创建时，验收预期成功但实际返回 127，确认失败原因是缺少 `run.sh`。实现后发现测试辅助函数以 CMake 列表展开参数时丢弃空字符串，导致 `--debug-dir "" --log ...` 错位；直接 `bash -x run.sh ...` 验证 Bash 数组保留空值，真实应用成功处理两帧。测试改用实际 debug 目录，避免 CMake 空参数丢失；直接空值调用也已验证成功。

### 2. 默认构建与完整测试

```bash
bash -n run.sh
cmake -DROOT=/home/wuming/Projects/shu_auto_aim_project \
  -DAPP=/home/wuming/Projects/shu_auto_aim_project/build/srm_auto_aim_app \
  -DSDK=/home/wuming/Projects/shu_auto_aim_project/build/libsrm_mvs_mock.so \
  -DOUTPUT_DIR=/tmp/opencode/srm-round18-launcher \
  -P tests/launcher_smoke.cmake
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

结果：Bash 语法检查和单独启动验收通过；CMake 配置/编译成功，完整 CTest **16/16 通过**。新增测试直接调用真实应用，MVS 设备层使用既有模拟 SDK。

### 3. 无 MVS/GUI 构建

```bash
cmake -S . -B /tmp/opencode/srm-mvs-disabled \
  -DCMAKE_BUILD_TYPE=Debug -DSRM_ENABLE_GUI=OFF -DSRM_ENABLE_MVS=OFF
cmake --build /tmp/opencode/srm-mvs-disabled -j2
ctest --test-dir /tmp/opencode/srm-mvs-disabled --output-on-failure
```

结果：配置、编译成功，完整 CTest **14/14 通过**，包括通过 `SRM_APP` 指向该构建的脚本验收。

### 4. 帮助和默认一条命令回放

```bash
bash run.sh --help
build/srm_auto_aim_app --help
bash run.sh
git diff --check
```

结果：脚本中文帮助和原应用完整帮助正常。默认命令成功回放 120 帧，生成 `replay_debug/latest/run.csv`、`summary.txt` 和 6 张检测图（序号 0、20、40、60、80、100）。摘要实际为 `processed_frames=120`、`log_rows=120`、`candidate_count=31`、`safe_count=120`、`error_count=0`、`nonzero_fire_request_count=0`，transport 收发与通信错误均为 0。默认未配置内参，应用如实打印内参提示。`git diff --check` 通过。

## 重要限制与后续安排

- 本轮验证为脚本、配置加载、离线运行和模拟 MVS 运行；没有真实相机、CDC 或云台测试。第十七轮的完整 MVS 4.7 开发头文件及实机采集待确认项继续见 `questions.md`。
- 默认 `demo.avi` 为本地素材，迁移项目需携带素材或修改文件路径。默认固定输出位置适合日常查看，需要保留结果时另设批次路径。
- 后续可直接编辑 `run.conf` 进行日常回放；进入 NUC 适配时使用 `list`、`info`、`mvs` 简化操作，并按既有现场清单记录结果。
