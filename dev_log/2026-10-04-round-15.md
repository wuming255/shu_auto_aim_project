## 遇到的问题及处理

1. 之前的离线 smoke test 只在手工命令中执行，容易出现“代码改了但入口路径未被 CTest 覆盖”的问题；已将确定性 PPM 输入和输出文件检查纳入 CTest。
2. 集成测试必须保持无硬件和无发射风险，因此测试显式使用 `--dry-run`、固定内参和仓库内样本，不验证真实相机、CDC 或命中效果。
3. 部署文档需要区分本地软件验证和现场事实确认，已明确把 MVS、USB CDC、云台、标定和发射步骤继续放在 `questions.md`。

## 尚未解决的问题

- 尚未绑定海康 MVS SDK；当前现场相机仍需在 `FrameSource` 接口上适配。
- 尚未在真实 NUC、真实 USB CDC、下位机和云台上验证权限、设备路径、状态字段、方向、延迟和标定。
- 尚未进行装弹、真实发射或任何非零 `fire_flag` 测试；应用默认仍保持 `fire_flag=0`。
- CTest smoke test 验证的是入口、输出和安全边界，不代表检测率、预测精度、命中率或现场实时性。

## 阶段结论

阶段八的软件主体和自动化交付准备已完成，当前交付物包括：

```text
可配置运行入口
+ 图片/视频离线回放
+ debug 图像
+ CSV 运行日志
+ key=value summary
+ 运行统计
+ CTest 集成 smoke test
+ 部署与交付文档
+ fire_flag=0 安全边界
```

真实设备适配和最终安全验收不由本轮本地测试代替，继续按照根目录 `questions.md` 集中执行。

## 后续安排

若继续开发，下一步不再是阶段八基础软件功能，而是根据 `questions.md` 进行现场环境确认、MVS/CDC 适配、标定、静态云台验证和在安全员许可下的最终测试；这些操作必须记录真实现场结果，不能用本地 smoke test 代替。
