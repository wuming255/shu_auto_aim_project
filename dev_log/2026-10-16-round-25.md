# 第二十五轮：固定守点、安全门与默认回放验收

日期：2026-10-16。本轮完成第二十四轮旋转诊断之后的固定守点、到点弹道、安全门和 transport 命令过期保护集成，并修复默认离线回放的输入方向配置。现场相机、云台、下位机语义和发射行为仍未验证。

## 本轮完成内容

- `FixedGuardController` 已接入 `AutoAimPipeline`：可靠旋转模型通过质量门后锁存守点，中心/半径/yaw 超阈值时重新定位；短暂丢失在保持窗口内保留瞄准但禁止开火；长丢失清除守点并要求重新捕获。
- 固定守点通过 `AimCompensator` 使用下位机弹速和预计飞行时间计算到点相位，并输出 `guard_command_valid`、`guard_target_visible`、`fire_window_valid` 和 `guard_phase_error_rad`。
- `SafetyController` 增加当前可见性、命中窗口、视觉开火意图、云台反馈新鲜度、云台误差和持续稳定时间门控。默认 `allow_visual_fire=false`，应用入口不提供视觉开火意图，默认仍保持 `fire_flag=0`。
- `SelfAimTransport` 增加 `command_max_age`。命令超过配置时间未刷新时，读取和周期发送退回全零安全命令；正式 CDC 帧布局未改变。
- 配置文件支持全部新增 `fixed_guard.*`、`safety.*` 和 `transport.command_max_age_ms` 键；应用支持测试覆盖这些键及命令行命令过期参数。
- runtime CSV 从52列扩展为56列；应用说明、架构说明、启动器帮助和默认配置已同步。

## 默认回放方向问题

首次执行 `bash run.sh` 时，`demo.avi` 触发：

```text
srm_auto_aim_app: calibration orientation does not match delivered frame orientation
```

根因是 `demo.avi` 没有 `.metadata.yml` sidecar。文件输入只使用文件方向声明和 `input.rotation_deg`，不会使用实时相机的 `camera.rotation_deg`；原配置交付方向为0°，而当前标定要求180°。先用单变量 `--file-rotation 180` 验证方向校验路径，再对完整视频做 A/B：声明 `input.orientation_deg=180` 且不旋转像素得到6个候选帧，额外旋转180°得到0个候选帧。因此默认配置改为声明视频已有180°方向、`input.rotation_deg=0`，保留实时相机独立的 `camera.rotation_deg=180`。视频检测结果仍很稀疏，方向选择不等价于现场标定或检测精度验收。

## 实际验证命令与结果

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
build/srm_auto_aim_app --help
bash run.sh
git diff --check
```

- 配置和构建成功；构建使用参考 MVS 头文件 fallback，未验证完整 SDK 4.7 ABI。
- CTest 全部通过：24/24。
- `--help` 返回0，输出54行。
- 默认 `bash run.sh` 返回0；处理687帧并写出1行 EOF，摘要为 `error_count=0`、`orientation_deg=180`、`candidate_count=6`、`safe_count=688`、`aiming_count=0`、`fire_ready_count=0`、`nonzero_fire_request_count=0`，CSV共689行（含表头），表头及数据行均为56列。
- 默认回放只证明离线输入、方向绑定、日志和安全默认路径工作；不证明实际标定、旋转预测精度、云台反馈语义或命中效果。
- `git diff --check` 通过。
