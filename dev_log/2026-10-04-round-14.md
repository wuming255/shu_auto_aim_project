# 第十四轮开发日志：阶段八集成验证与交付准备

日期：2026-10-04

## 本轮目标

在不接入真实相机、真实 USB CDC、云台、标定或发射设备的前提下，完成阶段八当前软件集成轮次：为已有 `srm_auto_aim_app` 增加可选 debug 图像、运行摘要、运行统计和更完整的 CSV 可观测性，并完成自动化和离线验证。

## 本轮实际完成

### 1. 运行耗时和统计模块

- 为 `RuntimeStepResult` 增加 `step_duration`，记录一次 `AutoAimRuntime::step()` 从开始读取帧到安全命令写入 transport 的 `steady_clock` 微秒耗时。
- 新增 `src/app/runtime_statistics.hpp/.cpp`，统计：
  - step、成功帧、EOF 和处理错误；
  - 检测候选数量；
  - `safe`、`aiming`、`fire_ready` 状态次数；
  - 非零开火请求次数；
  - 总/平均/最大 step 耗时；
  - transport 发送帧、接收帧和通信错误累计值。
- 正常 EOF 单独计入 `end_of_stream_count`，不再计入 `error_count`。
- 将统计实现加入 `srm_app_support` CMake target。

### 2. CSV 运行日志扩展

- `RuntimeCsvLogger` 新增 transport 快照参数，同时保持无快照调用的兼容默认值。
- CSV 新增字段：
  - `step_duration_us`；
  - `transport_sent_frame_count`；
  - `transport_received_frame_count`；
  - `transport_communication_error_count`。
- 主循环每次 step 后读取 transport 计数并写入日志。

### 3. 应用入口集成

- `srm_auto_aim_app` 集成 `RuntimeStatistics`。
- 新增 `--debug-dir PATH`：启动时创建目录，并保存 `TraditionalDetector::draw_debug()` 生成的无 GUI 图像。
- 新增 `--debug-every N`：按 `Frame.sequence` 控制保存频率，`N=0` 被拒绝；文件名为 `frame_000000.png` 等。
- 新增 `--summary PATH`：正常退出时写出 key=value 摘要，包含处理帧、日志行数、dry-run、耗时、安全状态、开火请求和 transport 统计。
- 新增配置键：
  - `runtime.debug_dir`；
  - `runtime.summary`；
  - `runtime.debug_every`。
- 保持默认和异常路径 `fire_flag=0`，dry-run 不启动 transport；输出失败时依靠 transport 析构路径停止后台线程。

### 4. 测试和文档

- 扩展 `tests/application_support_test.cpp`，覆盖：
  - 新增命令行参数；
  - 配置文件读取和命令行覆盖；
  - `--debug-every 0` 拒绝；
  - CSV 新列和 transport 快照；
  - 运行统计、摘要字段和正常 EOF 不计为错误。
- 更新：
  - `docs/application.md`；
  - `docs/architecture.md`；
  - `docs/development_plan.md`；
  - `docs/development_workflow.md`。
- 文档明确 debug、CSV、summary 的格式、使用方式和 `fire_flag=0` 边界。

执行：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
git diff --check
./build/srm_auto_aim_app --help
```

结果：

- CMake 配置成功；
- Debug 编译成功；
- CTest：`12/12` 通过，`100% tests passed`；
- `git diff --check` 通过；
- `--help` 正常显示 `--debug-dir`、`--debug-every` 和 `--summary`。

另执行离线 synthetic PPM 图片 smoke test：

```bash
./build/srm_auto_aim_app \
  --input image --source /tmp/shu_round14_eof_smoke/input.ppm --dry-run \
  --intrinsics 800,800,16,12 \
  --debug-dir /tmp/shu_round14_eof_smoke/debug --debug-every 1 \
  --log /tmp/shu_round14_eof_smoke/run.csv \
  --summary /tmp/shu_round14_eof_smoke/summary.txt
```

实际结果：

- `processed_frames=1`；
- `log_rows=2`（一帧数据行加一行正常 EOF）；
- 成功生成 `debug/frame_000000.png`、CSV 和 summary；
- summary 中 `end_of_stream_count=1`、`error_count=0`、`nonzero_fire_request_count=0`；
- CSV 中 `fire_flag=0`，dry-run 没有发送或接收 transport 帧。

以上是本地自动化、离线文件输入和 synthetic image 验证，不是现场效果验证。

## 遇到的问题及处理

1. 运行统计实现使用 `std::max`，初始编译依赖遗漏 `<algorithm>`；已补齐并重新配置、编译和测试。
2. 正常 EOF 在运行时结果中带有说明性 `error` 文本，若直接累计会把正常回放结束误报为处理错误；统计模块已按 `end_of_stream` 单独分类。
3. 主程序需要同时保留检测结果用于 debug 绘图和返回检测结果给运行时；当前通过 callback 保存最近一次 `DetectionResult`，只在检测成功且达到 debug 间隔时写图。

## 尚未解决的问题

- 尚未绑定海康 MVS SDK；当前输入仍为图片、视频和 OpenCV camera index。
- 尚未在真实 NUC、真实 USB CDC、比赛下位机和云台上验证权限、CDC 行为、方向、延迟、标定和状态字段语义。
- 尚未进行装弹、真实发射或任何非零 `fire_flag` 测试；项目当前应用入口仍保持 `fire_flag=0`。
- summary/CSV 统计是诊断信息，不包含正式协议原始帧，不能替代现场安全和命中测试。
- transport 的累计快照按每个 step 读取，后台线程并发下各计数之间不是同一个原子时刻的事务快照。
