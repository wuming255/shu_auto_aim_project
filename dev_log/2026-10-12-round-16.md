# 第十六轮开发日志：可选离线窗口调试

日期：2026-10-12

## 本轮目标

为图片和视频 dry-run 增加逐帧窗口，观察传统检测叠加图和亮度二值图，支持播放、暂停、单步和正常退出。窗口功能放在应用层，复用已有 `draw_debug()` 和 `DetectionResult::brightness_mask`。

## 本轮实际完成

- 新增 `src/app/debug_viewer.hpp`、`src/app/debug_viewer.cpp`：管理两个可缩放窗口、帧信息栏、播放等待、键盘、关闭按钮和窗口清理。
- `SRM detection` 显示当前图像、灯条、装甲板四角点和 ROI；`SRM brightness mask` 显示本帧二值图。无目标时仍更新，检测结果不可用时显示当前原图和零二值图。
- 新增 CLI `--show-debug/--no-show-debug`、`--start-paused/--no-start-paused`、`--playback-fps`，以及对应 `runtime.*` 配置键；CLI 继续覆盖配置文件。
- 窗口默认关闭，仅接受 dry-run 图片/视频。帧率为 `0` 时使用源帧率或回退到 30 FPS，非零值接受有限的 `[0.1, 1000]`；未启用窗口时拒绝非默认播放参数。
- 视频可首帧暂停，图片首帧自动暂停。任一窗口获得焦点后，空格暂停/继续，`n` 单步并保持暂停，`q`/Esc/关闭任一窗口正常退出；暂停时也响应 SIGINT/SIGTERM。
- 入口按需共享一次检测绘制，窗口显示每个成功读取的帧，`--debug-every` 单独控制保存。暂停等待不再次调用运行时，不重复 CSV 或图像保存。
- CMake 增加 `SRM_ENABLE_GUI`，HighGUI 为可选依赖，仅应用链接。关闭窗口支持的构建仍提供非 GUI 回放；缺少显示环境或窗口编译支持时，显式 GUI 请求返回清晰错误。
- 修复 EOF 和处理结果缺失时 CSV 的空字段分隔符，所有逻辑记录保持表头的 21 列；扩展应用支持测试，覆盖 GUI 参数、配置覆盖及缺失值后的安全/错误列对齐。
- 更新 `docs/application.md`、`docs/architecture.md`、`docs/deployment.md`，说明使用方式、构建选择、键盘操作、输出和播放时间边界。

## 验证命令与结果

### 1. 默认构建和无 GUI 构建

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure

cmake -S . -B /tmp/opencode/srm_round16_build_nogui \
  -DCMAKE_BUILD_TYPE=Debug -DSRM_ENABLE_GUI=OFF
cmake --build /tmp/opencode/srm_round16_build_nogui -j2
env -u DISPLAY -u WAYLAND_DISPLAY \
  ctest --test-dir /tmp/opencode/srm_round16_build_nogui --output-on-failure
```

结果：OpenCV 4.5.4；默认配置显示窗口支持 `enabled`，关闭配置显示 `unavailable (headless replay supported)`。两种配置均编译成功，各 `13/13` 项测试通过，包含应用 smoke test、新参数校验和 CSV 缺失值回归检查。

### 2. 帮助和无显示环境离线回放

```bash
./build/srm_auto_aim_app --help
env -u DISPLAY -u WAYLAND_DISPLAY ./build/srm_auto_aim_app \
  --input video --source demo.avi --dry-run --max-frames 60 \
  --debug-dir /tmp/opencode/srm_round16_headless_debug --debug-every 15 \
  --log /tmp/opencode/srm_round16_headless.csv \
  --summary /tmp/opencode/srm_round16_headless_summary.txt
```

结果：帮助包含新增参数。无显示环境回放成功，处理 60 帧、CSV 60 行，保存序号 0、15、30、45 四张图；`error_count=0`、`candidate_count=4`、`safe_count=60`、`nonzero_fire_request_count=0`，transport 收发和通信错误均为 0。CSV 列数、非开火值和保存数量另由临时验收脚本核对。

### 3. 合成视频与真实窗口交互

生成 640×480、10 FPS、16 帧的临时视频；两根红灯条在帧 0–3 和 8–11 出现，其余帧为黑背景：

```bash
ffmpeg -hide_banner -loglevel error -f lavfi \
  -i "color=c=black:s=640x480:r=10:d=1.6,drawbox=x=240:y=160:w=8:h=60:color=red:t=fill:enable='lt(n,4)+between(n,8,11)',drawbox=x=360:y=160:w=8:h=60:color=red:t=fill:enable='lt(n,4)+between(n,8,11)'" \
  -c:v ffv1 -pix_fmt bgr0 -y /tmp/opencode/srm_round16_mixed.avi
python3 /tmp/opencode/srm_round16_gui_check.py
```

临时脚本在 GTK3/X11 下启动本项目应用，通过 XTest 向应用窗口发送按键，通过窗口关闭事件检查退出，并截图比较刷新和暂停；检查前拒绝控制已有同名窗口，结束时清理测试进程。实际通过：

- 首帧暂停、`n` 单步、无目标帧的叠加图/二值图刷新、暂停冻结和 `q`；保存间隔为 4 时处理 5 帧仅保存序号 0、4 两张图。
- 空格播放/暂停，以及从二值图窗口操作 `n` 和 Esc。
- 分别关闭检测窗口或二值图窗口，写出 summary 并清理另一窗口。
- 暂停时的 SIGINT 和 SIGTERM 正常退出。
- 图片输入自动暂停，`n` 后进入 EOF 并退出。
- 视频 EOF：16 帧、额外一行 EOF、8 次候选；逐帧候选序列为 `1111000011110000`，端到端耗时 1.78 秒。
- `--loop --max-frames 20`：20 帧正常退出，端到端耗时 2.19 秒。
- `demo.avi --max-frames 10` 的窗口回放：10 帧正常退出，端到端耗时 0.53 秒。

各退出 summary 的 `error_count=0`、`nonzero_fire_request_count=0`、`transport_sent_frame_count=0`；视频 CSV 含 EOF 在内的列数和 `fire_flag=0` 均通过检查。截图产物包括 `/tmp/opencode/srm_round16_first_detection.png`、`srm_round16_first_mask.png`、`srm_round16_empty_detection.png`、`srm_round16_empty_mask.png`。

```bash
env -u DISPLAY -u WAYLAND_DISPLAY \

  --input video --source /tmp/opencode/srm_round16_mixed.avi --dry-run \

python3 /tmp/opencode/srm_round16_final_check.py
git diff --check
```

结果：无 GUI 构建处理 16 帧、CSV 17 行（含 EOF），保存 4 张图；候选序列符合合成视频，EOF 的空字段保留正确列位。最终脚本复核帮助、60 帧无显示回放、无 GUI CSV 和两种 GUI 不可用错误；默认构建无显示环境和关闭 GUI 构建显式请求窗口均返回码 1，错误分别为 `requires a desktop display` 和 `debug windows are unavailable in this build`。

另在原生桌面环境 `GDK_BACKEND=wayland` 下验证首帧处理后保持暂停，SIGTERM 退出码 0，summary 中处理 1 帧且非零开火数为 0。完整按键/关闭验证使用 GTK3/X11，原生 Wayland 检查限于启动、暂停和信号退出。`git diff --check` 通过。

临时视频、脚本、截图和验收输出位于 `/tmp/opencode`；窗口交互依赖桌面环境，CTest 继续使用无窗口测试。

## 遇到的问题及处理

1. GTK3 对 `WND_PROP_VISIBLE` 返回 `-1`，原先将其误判为窗口关闭，导致窗口提前退出。通过 GUI 探针和 gdb 确认后，增加 `WND_PROP_AUTOSIZE` 存在性回退，实际关闭两种窗口的验证均通过。
2. 测试脚本的直接 XSendEvent 按键未使窗口单步；改用 XTest 并让测试窗口获得焦点后，完整交互检查通过。应用本身无需强制 X11 后端。
3. EOF 回放暴露已有 CSV 缺失字段分隔符的问题，安全状态和错误列出现错位。补齐缺失帧/管线字段的分隔符，并验证 EOF 和有帧但无管线结果两种记录。

## 重要限制与后续安排

- 跟踪使用读帧时的单调时间戳；暂停和播放速度会改变帧间时间。窗口回放用于检测观察，不能据此评估实际目标角速度、预测精度或现场控制性能。
- GUI 事件处理和检测耗时会影响实际播放速度；窗口逐帧显示，不跳帧追赶。运行步骤耗时不包括窗口、保存和等待。
- 本轮数据和默认内参仅用于软件验收，未验证现场标定、检测率、命中率、MVS、真实 USB CDC 或云台行为。现场验证仍按 `questions.md` 执行。
- 本轮可选离线窗口功能已通过本地验收。后续可用实际录制素材观察灯条和装甲板筛选结果，再依据证据开展单独的算法改进轮次。
