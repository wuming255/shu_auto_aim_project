# 第 3 轮开发日志：输入抽象基础

日期：2026-10-04

## 本轮目标

在不进行现场实车、真实相机或下位机测试的前提下，根据校内赛规则、正式通信协议和参考项目的输入接口，完成可供后续视觉模块使用的通用图像输入抽象。

本轮只推进软件开发，不执行 `questions.md` 中的最终现场测试。

## 开始前的复用检查

- 当前项目此前没有相机或图像输入实现。
- 参考项目已有 `CameraBase` 的“图像 + `steady_clock` 时间戳”接口，以及基于 `cv::VideoCapture` 的 USB 相机输入实现。
- 参考项目的 `Camera` 工厂直接绑定 YAML、日志、线程队列和海康/迈德威视 SDK，不能在当前没有现场设备确认的阶段整体直接复制。
- 本轮复用了其统一图像/时间戳接口思路，采用小幅重构方式实现独立的离线/通用 OpenCV 输入层；没有复制旧通信协议或不必要的厂商耦合。

## 实际完成

- 新增 `src/io/frame_source.hpp/.cpp`，实现 `FrameSource`：
  - 单张图片输入；
  - 视频文件输入；
  - OpenCV camera index 输入；
  - 统一输出 BGR `cv::Mat`；
  - 输出 `steady_clock` 时间戳；
  - 输出单调序号和文件源时间；
  - 图片/视频 EOF 状态；
  - 图片/视频循环输入；
  - 文件输入 reset；
  - 可配置分辨率、帧率和 OpenCV backend；
  - 与参考项目 CameraBase 兼容的 `read(cv::Mat&, timestamp)` 便捷接口。
- 更新根目录 `CMakeLists.txt`：
  - 查找 OpenCV `core/imgcodecs/videoio` 组件；
  - 新增 `srm_frame_source` 静态库；
  - 新增输入层测试目标。
- 新增 `tests/frame_source_test.cpp`，使用临时生成图片验证：
  - 图片打开和 BGR 数据；
  - 图片 EOF；
  - reset 后重新读取；
  - loop 模式连续读取；
  - 兼容读取接口；
  - 空路径、缺失文件和非法帧率配置错误。
- 更新 `docs/architecture.md`、`docs/development_plan.md` 和 `docs/development_workflow.md`，记录输入层边界和本轮验证方式。

- `git diff --check` 未发现空白错误。

## 本轮遇到的问题及修复

1. 参考项目相机工厂依赖 YAML、日志和厂商 SDK，直接复制会把现场硬件依赖提前耦合到当前工程；本轮改为独立的 OpenCV 输入抽象，保留后续 MVS 适配接口。
2. 视频循环读取如果直接调用完整 `reset()` 会重置对外序号和时间戳；已改为循环播放只回到文件起点，保持序号和时间戳单调，显式 `reset()` 才重置序号。

## 尚未解决的问题

- 尚未实现目标检测、解算、跟踪、瞄准和安全开火决策。
